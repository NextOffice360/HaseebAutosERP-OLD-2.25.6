This local helper builds clean links for the desktop/mobile ERP and its three mobile apps. It does not deploy code, change permissions, sign you in, or repair Google's account session.

2. If Google says it cannot open the file

  1. Download this HTML file and open it in Chrome or Edge, not inside Google Drive, Gmail, WhatsApp, or another in-app file preview. Links may be blocked in a sandboxed preview.
  2. For a deployment set to Anyone, copy the clean URL into a new Chrome Incognito / Edge InPrivate tab while signed out. For Anyone with a Google account, sign in with one permitted Google account only in that private window before opening the same URL.
  3. On a phone, use Chrome Incognito or Safari Private browsing. Do not open it through the Drive app. The ERP uses the same URL and adapts to the smaller screen.
  4. In the Apps Script editor, choose Deploy → Manage deployments. Confirm Web app, Execute as: Me, and your intended access policy. Copy the URL ending in /exec. The editor URL, project ID, Drive share URL and redirected googleusercontent URL are not the app link.
  5. Publish saved source through Edit → New version → Deploy. Changing source or access settings in another deployment does not update the URL you are testing. Workspace policy or moved ownership may require the owner/admin to redeploy.
  6. If it still fails, send the exact failing URL, a screenshot, and whether a new doGet execution appears in Apps Script → Executions at that time. An execution with an error gives the next code error to investigate; no matching execution points toward routing/access, but is not proof of one specific cause.

Do not make the spreadsheet public, delete it, or disable Google security protections to solve a web-app opening error.

3. Recover the empty default tables separately

Install the complete v2.14.1 source in your existing project and Save. Run Setup.gs → diagnoseSeedData → Run to confirm the linked database. Then run Setup.gs → repairSeedData → Run, repeating only if the returned result says complete:false. Resolve any thrown error before proceeding.

Publish a New version afterward. Fresh recovery creates 9 users, 5 groups and 3 locations plus other defaults. Existing passwords and transactions are preserved. Products/stock are not imported; empty transaction sheets are normal. Change initial passwords or disable unused default accounts before business use.
